# 东盟协定义务实施矩阵

把数字经济框架协议（DEFA）与货物贸易议定书（TGP）的正式条款，转成成员国海关、电子交易、平台监管部门**可执行、可核验的国内事项**，并为企业提供只反映真实可用状态的公开视图。

## 业务规则

1. **条款拆解（秘书处）→ 事实确认（各国）**：秘书处把每项措施拆成六要素草稿——责任机关、法律修订、技术接口、预算、完成证据、适用豁免；成员国只确认本国事实，秘书处负责跨国依赖与互认条件。
2. **门槛全部通过才算落实**：条款已生效、法律已实际施行（颁布待施行不算）、技术接口已上线（pilot/uat/build 不算）、预算已拨付、完成证据已获接受、无阻断性豁免、前置措施已落实。
3. **未生效条款不得标成已落实**：国内全部就绪但条款未生效时，只能登记为 `ready_pending_entry`（国内就绪待生效）。
4. **全程留因**：国内计划调整、期限延长、部分完成、证据退回都必须记录原因；审查与问询记录只追加、不改写。
5. **跨国互认**：跨境措施在成员对之间还须通过双边符合性测试（AEO 另须互认安排生效），且秘书处跨国依赖登记中无阻断项。
6. **企业视图最小化**：企业只看到 `available`（已具备法律与技术条件并附可用日期）或中性的 `not_available`；预算、豁免、延期、退回原因、建设阶段、哪一方阻断互认等一律不公开。

## 分区保存（多国敏感材料隔离）

```
fixtures/zones/
├── public/                 公共区：措施目录、秘书处发布的公开摘要
├── secretariat/            秘书处区：跨国依赖、双边符合性、互认门槛配置
└── member-<国家>/          成员国区（brn/sgp/tha）：profile/tasks/evidence/exemptions/reports/inquiries
```

| 角色 | 公共区 | 秘书处区 | 本国分区 | 他国分区 |
|---|---|---|---|---|
| 秘书处 secretariat | 读写 | 读写 | 只读 | 只读 |
| 法律与技术审查人员 reviewer | 只读 | 只读 | 只读 | 只读 |
| 成员国 member:XXX | 只读 | 不可见 | 读写 | 不可见 |
| 企业信息发布人员 publisher / 企业 enterprise | 只读 | 不可见 | 不可见 | 不可见 |

## 模块

- `src/zones.js` — 分区标识、角色权限矩阵、受控读写、整库加载与分区归属校验
- `src/catalog.js` — 公共条款/措施目录索引
- `src/matrix.js` — 六要素草稿、成员确认、逐门槛评估（含前置措施递归与环检测）
- `src/reports.js` — 季度回报编制与校验（调整/延期/部分完成/证据更正强制留因）
- `src/review.js` — 证据提交与审查（退回留因、结论只追加）
- `src/inquiries.js` — 同行问询（仅被问询方可答、秘书处登记跨国依赖、超时升级留痕）
- `src/recognition.js` — 互认门槛检查（条款门/双方法门/双边符合性/互认安排/依赖登记）
- `src/public.js` — 秘书处生成公开摘要；企业成员视图与措施视图
- `contracts/` — 共享资料与六要素事项文档的 JSON Schema
- `fixtures/context.json`、`fixtures/zones/` — 不含真实个人信息或凭据的公开/分区样例
